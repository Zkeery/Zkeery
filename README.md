### 关于我 / About

你好，我是 Zkeery，一名有测试和后端开发背景的 AI 产品经理。

做过测试，让我习惯追问：什么才算做好了，哪些场景会出问题，结果该怎样验证。做过后端开发，让我在设计产品时，也会考虑接口、数据流和系统边界，判断方案是否可行、实现成本在哪里。

现在，我把这些经验带进 AI 产品：从用户的问题出发，明确 AI 适合承担的任务，用原型验证想法，用评测与反馈推动迭代。这里记录我的产品拆解、Agent 探索，以及动手实现的项目。

### 我如何做 AI 产品 / Approach

| 经历与视角 | 带到 AI 产品中的判断 |
| :--- | :--- |
| **测试经历 · 定义质量** | 把“效果不错”拆成可验证的标准，关注典型场景、异常输入和失败后的处理方式。 |
| **后端开发经历 · 判断可行性** | 从接口、数据流与系统边界理解方案，把模型能力放进实际业务流程，考虑响应时间、成本与稳定性。 |
| **产品视角 · 做出取舍** | 明确用户要完成的任务，判断哪里值得用 AI、哪里需要确定性规则，再确定优先级与验收方式。 |

### 项目与实践 / Selected Work

**[Lovart 产品拆解 ↗](https://github.com/Zkeery/lovart-deconstruction)**<br>
围绕用户旅程、Agent 流程、提示词与架构展开分析，并保留截图证据。从可观察的产品行为出发，理解 AI 能力如何组织成用户体验。

**[证据驱动产品拆解 Skill ↗](https://github.com/Zkeery/evidence-based-product-deconstruction)**<br>
把拆解方法整理成可复用的 Agent Skill：记录证据，区分事实、推断与待确认项，输出结构化报告，让产品判断可以追溯和复查。

**[工位行动 ↗](https://github.com/Zkeery/office-health-app)**<br>
面向久坐上班族的应用原型，包含预算餐单、碎片运动、七日计划与地图。用原型把场景变成具体流程，并通过业务回归检查验证预算约束、重复操作和跨日记录等规则。餐单与会员为演示数据。

**[macOS 番茄钟 ↗](https://github.com/Zkeery/pomodoro)**<br>
围绕专注场景实现桌面小工具，包含工作与休息切换、通知和本地记录。在具体交互中打磨产品细节。
